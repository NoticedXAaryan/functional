# Small, ordered tasks for the implementing AI

Work on one numbered task at a time. Do not start with a redesign of the entire App.tsx. Read the applicable source through the code graph first. Respect the existing user's no-testing instruction; the acceptance items below are requirements, not authorization to run tests or create records. Keep a ledger of unverified behaviour.

## 00 · Establish the exact baseline

- Read git status and preserve unrelated staged files, especially staff auth and migration 015.
- Obtain the deployment strategy and actual public/staff/API URLs. Record deployed commit and migration maximum without printing secret values.
- Identify whether staff auth uses cookie sessions or OIDC in the live environment. Identify API origin, worker, DB and object store owners.
- Output `docs/ui/implementation-status.md` with verified facts, unknowns and selected next task. Do not replace user-reported deployment with an invented diagnosis.
- Stop dependent backend/deployment work if the strategy is unavailable. Assets and presentational work can continue.

## 01 · Install the visual foundation

- Copy chosen assets from this kit into the two app public directories through one repeatable copy step.
- Add `tokens.css` scoped to `.bs-ui`. Use system fonts; don't install font packages.
- Integrate the five presentation primitives after adapting imports and accessibility requirements from COMPONENTS.md.
- Keep old routes working. Do not rename storage keys, API paths or DB values.
- Deliver one shared shell with actual language control, working exit callback, visible focus, footer and no redundant branding.
- Acceptance: style source matches tokens; no unused illustration blocks the main CTA; control minimum sizes match spec. Record whether rendering was observed.

## 02 · Apply branding safely

- One brand constant for Bal Setu / Nithari Alert / descriptive label; do not duplicate strings across apps and worker templates.
- Change visible titles, header labels, HTML titles, notification title and icon paths together.
- Preserve `/alerts/{id}`, old icon alias and `savera.subscription.v1` management credentials.
- Use original source and generated derivative per ASSETS.md. Do not source a victim photograph or invent an incident story.
- Acceptance: remaining old names occur only in intentionally retained technical/historical references, documented by filename.

## 03 · Connect availability and navigation

- Implement C01, C11, C12 and the new route transitions with in-memory draft preservation.
- `/config` is the authority for actual feature availability and operator label. No hardcoded online indicator.
- Hide microphone/enrollment controls unless supported and operational; explain useful alternatives.
- Loading has a timeout and retry; production config must not fall back to localhost.
- Acceptance: every visible navigation control has a real destination. No dashboard role picker for children.

## 04 · Accept a choice-only request

- Extend case validation to accept a meaningful selected intent without narrative. Keep existing session/routing/idempotency/permission checks.
- Update the API contract before implementing C02–C06. Voice remains disabled until task 09.
- Add explicit in-app reply consent v2, nullable for legacy records; do not backfill legacy no-contact to yes.
- C05 shows actual receiving team. A failed route cannot yield a receipt.
- Acceptance: receipt is server-backed; same-operation retries cannot produce two cases. Describe evidence separately if tests are not allowed.

## 05 · Repair and align staff access

- Apply the current deployed auth strategy, not the historic README by assumption.
- Resolve same-origin proxy/CSRF/cookie rules from doc/06; parse client IP before INET storage; recheck active role/org on requests; align expiry.
- Preserve existing sign-in work. Do not revert to demo passwords or disable CSRF to pass requests.
- Implement S01/S15 and actual expired-access handling. MFA/recovery comes from the selected maintained auth system.
- Acceptance: staff credentials stay out of localStorage and client bundles; offboarding removes access including media.

## 06 · Implement conversations without fixed access times

- C09 reads actual messages and sends through the canonical API, with idempotency.
- S02–S06 show authorized cases, assignment state and text replies; separate private team note mode.
- New explicit in-app consent permits anytime replies; old restrictive consent remains unchanged until child updates it.
- Add real-data closure/read-state handling; do not label assignment as read.
- Acceptance: no private push generated by a message. Permission failure does not leak message content.

## 07 · Add secure memorable return access

- Add forward migrations for device/card credentials, expiry and revocation. Keep current long-code access valid until expiry.
- Establish reviewed word vocabulary and stable IDs before enabling three-word choice. No demonstration list in production.
- Implement C07/C08 subflows from DECISIONS.md and parent doc/04, including shared-device opt-out.
- A fresh device cannot access a report with words alone. Persistent cookie requires explicit choice.
- Acceptance: no global phrase lookup, no credential in URL/log, recovery rotation cannot strand the only credential, rate limits never mutate other sessions.

## 08 · Build private media infrastructure

- Provision only an authorized private store; paid resources require budget authorization. Never place child media in public frontend assets.
- Implement upload intent, ownership binding, validation/processing, finalize, no-store authorized playback, expiry/orphan cleanup and attachment association.
- Add individual voice capability flag and quota handling. Keep voice UI off while infrastructure is incomplete.
- Acceptance: only ready, same-owner attachments can enter a message; revocation blocks new reads; no public or long-lived bearer URL.

## 09 · Add voice to child and staff screens

- Implement shared Recorder state machine from parent doc/04, not a decorative mic button.
- Microphone permission only on tap; preview before final Send; no autoplay. Stop on exit/hide/expiry.
- Staff voice requires typed equivalent; child voice does not. Listen uses approved local speech capabilities only; no default cloud transcription.
- Integrate C03/C09/M02/A03/S03/S06/S09 after backend readiness. Treat signed upload and message commit as separate steps.
- Acceptance: errors retain text/choice paths; blob URLs and tracks cleaned up; selected MIME is actually supported.

## 10 · Simplify missing-child and sighting intake

- Missing report remains private; no direct activation call from public client.
- Acceptance: user sees private receipt, never “Alert sent” for an unreviewed report.

## 11 · Connect nearby public alerts

## 12 · Complete operator lifecycle

- S07–S14: transfer with acknowledgment, closure, private tip review, independent alert approval, explicit activation, withdrawal/resolve and staff/area administration.
- Maintain independent routing; no self-approval or stale approved payload after an edit.
- Worker queue and heartbeat are real; a log line is not notification delivery or escalation acceptance.
- Acceptance: pending/failed actions visible; terminal alerts hide identifying details. Never invent eligible staff or jurisdictions.

## 13 · Reconcile language, accessibility and release evidence

- Review every activated locale across all 38 screen recipes, shared errors, notifications and voice instructions. Unreviewed locales stay disabled.
- Record implemented, unavailable, unverified and blocked features by ID. Do not equate generated board images with verified UI.
- When permitted, use actual supported-device and security-boundary verification; otherwise explicitly retain a not-verified status and do not declare complete beta readiness.
- Update README with verified live URLs, sign-in instructions and real scope. Keep secrets out of README.
- Commit only intended task files, preserving unrelated staged changes. Push when authorized. Deploy compatible layers in migration order with a rollback record.
