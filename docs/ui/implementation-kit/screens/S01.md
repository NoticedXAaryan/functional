# S01 · Staff sign in

Target route: `/sign-in`. Layout: **staff_list_detail**. Design only.

## Build in this exact visual order

1. Shared header: Bal Setu, Language, Leave this page. Staff shell uses role-appropriate navigation and Sign out instead of a private-help return flow.
2. Back control to the actual previous step, preserving the in-memory draft.
3. Heading: **Staff sign in**.
4. Supporting text: “Use your own staff account.”
5. Username or organization sign-in.
6. Password when session auth is deployed.
7. Show password.
8. Primary button: **Sign in**.
9. Secondary actions: Back to Bal Setu → public_home.
10. Footer: Other ways to get help, Privacy, Staff sign in (public screens only).

## Required behaviour

Primary action contract: `deployed_auth_then:S02`. Required capability: `deployed_staff_auth`. Replace braced values only with authorized API data. If required real data is absent, show a truthful unavailable state; never display the braces or invent a value.

Never infer success from time elapsed, a click, or a local state toggle. Use the actual committed API outcome.

Keep input labels visible; do not turn headings into placeholder text. Buttons are semantic buttons, navigation is a link, mutually exclusive choices use a labelled radio group or equivalent accessible single-select pattern. Do not ship the strings “from API”, action-contract tokens or dependency names as user content. They are instructions to the implementer.

## States to implement

- Loading: bounded wait, then Retry.
- Empty: specific explanation and next useful action; no invented records.
- Offline: retain unsent data only in memory; say it has not been sent.
- Submission unconfirmed: retry the same operation ID and payload.
- Permission denied: explain the available alternative; do not retry OS prompts automatically.
- Server rejection: preserve draft, translate stable error code, focus relevant field.
- Expired access: hide private content, stop media, open return/sign-in flow.
- Quick exit: stop capture/playback and discard private memory immediately.

## Screen-specific rules override the generic recipe

No Sign out control before sign-in. Use the real deployed auth method; do not render both unrelated login forms. Recovery must be supported by that method, not a dead link.
